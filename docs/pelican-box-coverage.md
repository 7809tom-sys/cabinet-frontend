# Pelican cabinet-box coverage

Generated by `npx tsx scripts/pelican-box-coverage.ts` from the catalog fixtures the Designer's own tests use
(`client/src/lib/__fixtures__/autoDesignRealCatalog.json`, `autoDesignMatrixCatalog.json`, `ovenCabinetRows.json`).
It reads fixtures only: no production database rows are read or written.

"Available" means both halves hold:

1. the **auto builder / auto-designer** can place the box (a run piece, a measured anchor, a corner, or — for a tall oven/pantry — a pick from the tall pop-up), and
2. the **3D Designer** can draw it, which needs a real width, height, and depth plus a drawing rule.

Roll-out trays, valances, moldings, panels, and fillers are **not boxes**. They stay add-on accessory lines, are
never auto-built as cabinet boxes, and are listed separately at the end.

## How a box is decided

- Auto-builder path: `client/src/lib/pelicanBoxCoverage.ts` (`autoBuilderPath`), which mirrors what `runAutoDesignLayout` seats.
- 3D Designer: `client/src/lib/pelicanBoxCoverage.ts` (`threeDDesignerCanDraw`) with the shared accessory split in `shared/designerEligibility.ts`.
- Tall oven/pantry auto-placement: `client/src/lib/autoDesignTallCabinets.ts`.
