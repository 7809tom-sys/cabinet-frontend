# Pelican Elemental mosaics: penny rounds and the two photo-less sheets

Short note for the team. Source of truth for how the Designer draws a Pelican mosaic is
`client/src/lib/mosaicCatalog.data.ts` (static, generated by `scripts/build-mosaic-catalog.py`).
Products, prices and visibility are database rows (`pelican_products`) owned by cabinet-backend.

## Added in this change

| SKU | Sheet (published) | Material | Photo | Texture |
| --- | --- | --- | --- | --- |
| Carrara Penny Round | 11.14 x 12.09 x 8 mm | marble | yes, from buildpelican.com | `client/public/textures/mosaics/carrara-penny-round.webp` |
| Calacatta Gold Penny Round | 11.14 x 12.09 x 8 mm | marble | yes, from buildpelican.com | `client/public/textures/mosaics/calacatta-gold-penny-round.webp` |

- New chip pattern kind `penny` (round discs). Every mosaic without a curated row gets the generic seamless sheet spec, so no per-product rendering code is needed.
- Scale is `joint-derived` (an estimate, like most of the catalog). The published size order (11.14 x 12.09) is the opposite of the landscape photo (about 12.09 wide by 11.14 tall), so the build could not use the sheet itself as the ruler. Check against Pelican's spec sheet before treating the module size as exact.
- The size and material text come from Pelican's 7/1/2026 price list. The storefront page does not publish a sheet size.

## How the build was run

`scripts/build-mosaic-catalog.py --catalog <rows.json>` needs the Tile & Mosaic rows as JSON (normally exported from the catalog DB, which this repo cannot reach). It was run on just the two penny-round rows in a scratch directory and the two generated entries were added to `mosaicCatalog.data.ts` by hand, so no existing entry or texture was regenerated. Re-run it with a full DB export before the next full rebuild.
